## П1. `total` в ответе нет

**В доке:** Response 200 — ровно `{"data": [...]}`, `total` только в части 3 как открытый вопрос №1.
**Что вы могли видеть:** сервис какое-то время отдавал `{"data": [...], "total": 3}` — вопрос №1 просочился в код раньше решения и в неполной форме, без `limit` и `offset`.
**Стало:** поле убрано, ответ соответствует доке буквально.

```json
{
  "data": [
    {
      "id": 3,
      "title": "Samsung Galaxy S24",
      "description": "Новый телефон в заводской упаковке",
      "price": 72000,
      "imageUrl": "https://example.com/samsung.png"
    }
  ]
}
```

**Вам:** если успели читать `total` — уберите, поля больше нет. «Страницы кончились» по-прежнему определяется только тем, что вернулось меньше, чем `limit`.

Вопрос №1 остаётся за вами: если нужна нумерованная пагинация или счётчик «найдено N» — скажите, и ответ станет таким, как предложено в доке, одним изменением: `{ "data": [...], "total": 137, "limit": 20, "offset": 0 }`.

## П2. У `offset` есть верхняя граница: `100000`

**В доке:** `offset >= 0`, верхней границы нет.
**Как есть:** граница существовала в коде с самого начала, просто не попала в доку. Это не новое ограничение.

| Запрос | Ответ |
|---|---|
| `?offset=100000` | `200` |
| `?offset=100001` | `400`, `message: "Failed to parse: offset must be an integer between 0 and 100000"` |
| `?offset=-1`, `?offset=abc` | `400`, то же сообщение |

**Вам:** для «показать ещё» и бесконечного скролла это недостижимо — на `limit=20` это 5001-я страница. Но если `offset` попадает в приложение из URL или внешней ссылки, клампите его у себя, чтобы вместо 400 показать пустую выдачу или первую страницу. Формула `offset = (N-1) * limit` из Флоу 2 в силе при `offset <= 100000`.

## П3. У `q` есть лимит длины: 200 символов

**В доке:** `q - string`, ограничений нет; `400` описан только для `limit` и `offset`.
**Как есть:** ограничение тоже было в коде с самого начала.

| Запрос | Ответ |
|---|---|
| `q` длиной 200 символов | `200` |
| `q` длиной 201 символ | `400`, `message: "Failed to parse: q must not exceed 200 characters"` |
| 200 символов + пробелы по краям | `200` — пробелы обрезаются **до** проверки длины |

Считаются символы, не байты: 200 русских букв — валидный запрос.

**Вам:** обрезайте `q` до 200 символов перед отправкой. Стреляет это тогда, когда пользователь вставляет в поиск скопированный абзац — сейчас он получит ошибку вместо пустой выдачи. На результаты обрезка не влияет, такие запросы всё равно ничего не находят.

**Правка к Response 400:** причин `400` теперь три — `limit` или `offset` вне диапазона либо не число, **либо `q` длиннее 200 символов**.

## П4. В теле 400 конкретика переехала из `error` в `message`

**В доке** пример тела: `error` = `"failed to bind query"`, `message` = `"Failed to parse: invalid key/value in query"`, с оговоркой «текст `message` может стать конкретнее (с указанием поля)».
**Что было на самом деле:** ровно наоборот — конкретика уходила в `error` (`"failed to bind query: limit must be an integer between 1 and 50"`), а `message` оставался общим.
**Стало так, как обещано в доке:**

```json
{
  "error": "failed to bind query",
  "message": "Failed to parse: limit must be an integer between 1 and 50"
}
```

Фактические тексты `message`:

| Причина | `message` |
|---|---|
| `limit` не число или вне 1..50 | `Failed to parse: limit must be an integer between 1 and 50` |
| `offset` не число или вне 0..100000 | `Failed to parse: offset must be an integer between 0 and 100000` |
| `q` длиннее 200 символов | `Failed to parse: q must not exceed 200 characters` |

**Вам:** если показываете или логируете текст ошибки — берите `message`, он теперь называет поле. Форма тела не изменилась: всегда `error` + `message`, код всегда `400`. `error` считайте стабильным, `message` — нет: **не парсите его**, только показывайте.
